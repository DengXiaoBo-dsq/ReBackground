text

技术栈：Kotlin + OpenGL ES 3.0
目标：对标 Procreate / Rebelle 的顶级绘画体验
当前状态：Phase 2 完成，采用 Gate 路线重构 Brush Kernel
下一步：G0 基线 + 最小可观测性 + Wet Engine 接口预留

第五部分：坐标系（关键，易错）
text
【3 个坐标系】
Screen（屏幕像素）   = GLSurfaceView 尺寸
Document（文档像素） = 用户设置的画布尺寸
NDC（[-1, 1]）       = 归一化设备坐标

【变换链】
viewToDocument（PaintEngineController）:
  screen 像素 → screen NDC
              → 除以 fitScale 得到 canvasVirtualNDC
              → 逆用户变换（旋转 / 缩放 / 平移）
              → document 像素

present.vert:
  screen NDC → 除以 canvasHalfNdc
             → 用户变换
             → vTexCoord

【关键不变量】
viewToDocument 与 present.vert 严格互逆
fitScale = min(screenW/docW, screenH/docH)
禁止修改：viewToDocument / present.vert 的变换链（互逆性一旦破坏会全乱）。

第六部分：FBO 布局
FBO	格式	用途	尺寸
canvas	RGBA8	画布底层（白底 / 图片）	document
pigment	RGBA16F	历史颜料（ping-pong）	document
pigmentPingPong	RGBA16F	Mixbox 中转	document
stroke	RGBA16F	当前笔	document
composite	RGBA8	最终显示	document
velocityField	RG16F	速度场（禁用中）	document/2

第八部分：Wet Engine 接口（架构边界）
8.1 核心原则
现在锁架构，不锁数值方案。

现在必须确定：

text
✓ Wet Engine 是独立 Material Engine
✓ Brush 只负责生成 Deposit
✓ Wet 不直接修改 Brush Source
✓ Wet 需要可测试的不变量
✓ Backend 与 Render 解耦
✓ ES 3.0 是基础兼容后端
现在可以暂不确定：

text
○ 最终分辨率（HALF / FULL / ADAPTIVE）
○ FBO 数量
○ Advection solver（Semi-Lagrangian / BFECC / MacCormack）
○ Edge model
○ 是否用 Compute Shader
○ Tile 尺寸
8.2 六个核心接口（G0 建骨架）
kotlin
// 1. WetMaterialEngine —— 未来 G6 的入口
interface WetMaterialEngine {
    fun beginStroke(stroke: Stroke, definition: BrushDefinition)
    fun deposit(deposit: MaterialDeposit)
    fun step(dt: Float)
    fun endStroke(strokeId: Long)
    fun resolve()
}

// 2. SimulationBackend —— Fragment / Compute 抽象
interface SimulationBackend {
    fun initialize(capabilities: PaintCapabilities)
    fun inject(deposit: MaterialDeposit)
    fun step(dt: Float)
    fun resolve()
    fun collectMetrics(): SimulationMetrics
}

// 3. SimulationResolutionPolicy
enum class SimulationResolution { FULL, HALF, QUARTER, ADAPTIVE }
interface SimulationResolutionPolicy {
    fun choose(canvasSize: Size, activeArea: Rect,
               quality: QualityTier, gpuTier: PerformanceTier): SimulationResolution
}

// 4. SimulationScheduler
enum class SimulationState { ACTIVE, QUIESCENT, FROZEN }
interface SimulationScheduler {
    fun notifyInput()
    fun update(dt: Float): SimulationState
}

// 5. MaterialState —— 逻辑状态（不是 FBO）
data class MaterialState(
    val waterMass: Float,
    val mobilePigmentMass: Float,
    val boundPigmentMass: Float,
    val velocity: Vec2,
    val dryness: Float
)

// 6. SimulationMetrics
data class SimulationMetrics(
    val waterMass: Double,
    val mobilePigmentMass: Double,
    val boundPigmentMass: Double,
    val maxVelocity: Float,
    val activeArea: Float,
    val nanCount: Int,
    val infCount: Int
)
8.3 术语约定
text
✓ 使用：DepositedPigment 或 BoundPigment
✗ 不再用：FixedPigment（暗示"永不动"，不对）
