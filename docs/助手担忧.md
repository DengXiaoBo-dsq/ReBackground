# ReBackground Wet Engine

## 技术决策、数值模型与未来实施约束

**目的：**

本文件不是要求现在立即实现 G6/G7。

它的目的只有三个：

1. 纠正目前对 Wet Solver 的一些错误或过早结论。
2. 在 G0~G5 实施期间提前锁定**不会影响前面架构的接口和数学边界**。
3. 等 G5 完成后，可以直接进入 Wet Core，而不需要重新设计 Brush Kernel。

---

# 1. 第一原则：现在不要锁死 Wet Solver 的最终实现

你提出：

```text

```

这五个问题不能现在全部拍板。

正确区分：

## 现在可以暂不确定的


也就是说：

> **现在锁架构，不锁数值方案。**

这是整个项目必须采用的原则。

# 3. Wet Engine 的第一版状态模型

建议未来采用：

```text
W = water depth / water mass density

M = mobile pigment mass

B = deposited/bound pigment mass

U = velocity

P = static paper properties

D = drying/binding state
```

但注意：

> `FixedPigment` 这个名字从现在开始建议逐步改成 `DepositedPigment` 或 `BoundPigment`。

原因是“Fixed”容易造成错误理解。

真实绘画中：

```text
已经沉积
```

并不意味着：

```text
永远不会重新移动
```

尤其是重新加水时。

这正是 Backrun / rewet 的来源之一。

---

# 4. 不要把 Water 简单理解成“水颜色”

Water 是：

```text
标量场
```

例如：

```text
W(x,y)
```

它代表局部：

```text
水量 / 水层厚度 / 相对湿度容量
```

它不是：

```text
RGB
```

也不是：

```text
alpha
```

---

# 5. Mobile Pigment 也应该是“质量”，不是颜色

逻辑上：

```text
M(x,y)
```

表示：

> 当前仍然能够被水移动的颜料量。

颜色只是这个颜料质量的附加状态。

所以概念上：

```text
Pigment:
    mass
    composition/color
```

而不是：

```text
RGB = pigment
```

---

# 6. Deposited Pigment 也同理

```text
B(x,y)
```

表示：

> 已经沉积到纸上的颜料量。

但是它仍然可以有：

```text
rewettable fraction
```

因此未来可以有：

```text
B_mobile
B_bound
```

但第一版本可以简化为：

```text
B
+
Dryness
```

由 Dryness 决定部分 B 是否能重新激活。

# 7. 一个非常重要的数学关系

Wet Engine 最终不应该只是：

```text
Water -> blur
```

而应该至少符合：

## Water

$$
\frac{\partial W}{\partial t}
+
\nabla\cdot(WU)
=
S_{water}
-
A_{water}
-
E_{water}
$$

其中：

```text
S = brush / rewet injection
A = paper absorption
E = evaporation
```

---

# 8. Pigment

Mobile pigment：

$$
\frac{\partial M}{\partial t}
+
\nabla\cdot(MU)
=
\nabla\cdot(D\nabla M)
-
R_{deposit}
+
R_{rewet}
$$

Deposited pigment：

$$
\frac{\partial B}{\partial t}
=
R_{deposit}
-
R_{rewet}
$$

这里最重要的是：

```text
Mobile
+
Deposited
```

是一个可转换系统。

---

# 9. 这意味着一个非常重要的质量守恒

在封闭区域，没有吸收、蒸发、删除的时候：

```text
initialMobile
+
initialBound
+
injectedPigment
=
currentMobile
+
currentBound
```

也就是说：

# 不是要求 Semi-Lagrangian 本身完美守恒。

而是要求：

> **整个 Material Engine 的质量预算可解释。**

这比单独盯着 advection 更重要。

---

# 10. Semi-Lagrangian 的问题，你的担忧是对的

传统 Semi-Lagrangian：

```text
backUV = uv - velocity * dt
new = sample(old, backUV)
```

优点：

```text
稳定
简单
允许比较大的时间步
非常适合实时交互
```

缺点：

```text
数值耗散
细节丢失
质量可能漂移
```

这一点在数值计算文献中是明确的；Semi-Lagrangian 的大优点正是稳定和效率，而其经典缺点之一就是不严格守恒。

---

# 11. 但是你的另一个结论不正确

不能说：

> “Semi-Lagrangian 做不出 Edge Darkening。”

这是错误的。

原因：

## Edge Darkening 不是 Advection 算法本身产生的。

它来自：

```text
Water Distribution
+
Evaporation
+
Paper Absorption
+
Pigment Transport
+
Pigment Deposition
```

Advection 只是其中负责：

```text
把水和颜料移动到哪里
```

的一个算子。

---


因此：

```text

```

依然可以作为第一版 transport solver。

# 24. Wet-on-Wet 的正确融合

假设：

```text
旧水：
W0

旧速度：
U0

新水：
W1

新速度：
U1
```

不要：

```text
U = mix(U0,U1,0.5)
```

而应近似使用：

$$
P = WU
$$

即水量加权的“动量”概念：

$$
U_{new}
=
\frac{W_0 U_0 + W_1 U_1}
{W_0 + W_1}
$$

这才是一个有意义的基础融合。

---

# 25. 这个公式还可以加入 Brush Impulse

例如：

$$
U_{new}
=
\frac{
W U
+
\Delta W U_{brush}
}{
W+\Delta W
}
$$

然后再进入：

```text
Damping
+
Paper Resistance
+
Height Gradient
```

这样：

> Brush 不“直接控制整个 Velocity Field”，而是向已有水场施加一个局部动量输入。

这会比：

```text
velocity = mix(old, brushVelocity, alpha)
```

自然很多。

---

# 26. Wet-on-Wet 的 Pigment 则是“质量相加”

例如：

```text
M0 = 旧颜料质量
M1 = 新颜料质量
```

总量：

```text
M = M0 + M1
```

如果使用 Mixbox latent：

$$
Z_{new}
=
\frac{M_0 Z_0 + M_1 Z_1}{M_0+M_1}
$$

这正好与 Mixbox 官方提供的 latent mixing 形式一致：其公开实现支持把 RGB 转到 latent，并对 latent 分量按比例混合，再转换回 RGB。其 latent 实际包含 7 个分量，而不是简单 3 通道 RGB。
