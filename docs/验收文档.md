# ReBackground Paint Engine

## G0-G8 自动化测试、量化验收与参数调优技术规范

**文档用途：**

本文件直接交给 ReBackground 执行助手，用于：

* 自动化测试；
* Gate 验收；
* 参数调优；
* 回归测试；
* GPU Shader 调试；
* 绘画效果量化；
* Wet Engine 后续数值模拟验收。

---

# 1. 最高级工程原则

执行助手必须遵守以下顺序：

```text
实现
 ↓
测试
 ↓
采集指标
 ↓
判断失败层级
 ↓
修改一个参数/一个逻辑
 ↓
重新测试
 ↓
全部通过
 ↓
进入下一 Gate
```

禁止：

```text
修改
 ↓
肉眼感觉变好了
 ↓
直接 PASS
```

也禁止：

```text
指标不通过
 ↓
直接放宽阈值
```

---

# 2. Gate 的定义

整个项目分为：

```text
G0  Baseline / Observability
G1  StrokeFrame
G2  Brush Fidelity
G3  Shape / Grain / Phase / Rake
G4  Dynamics
G5  Dry Material
G6  Wet Core
G7  Advanced Watercolor
G8  Performance / Stability
```

每个 Gate 必须：

```text
PASS → 进入下一 Gate
FAIL → 修复当前 Gate
BLOCKED → 补充测试数据
```

不得跳级。

---

# 3. 验收标准的性质

本文中的所有数字：

> **均为 ReBackground 内部工程验收目标，不是 Procreate、Krita 或其他商业软件公开的官方内部指标。**

这些数字的作用是：

```text
让执行助手有明确的停止条件
```

而不是声称：

> “行业规定就是这个数字。”

# 14. 特别注意 `jump`

禁止使用：

```text

```

因为：


```text

```

---

# 15. 特别注意 `oob`

允许：

```text
expectedTextureDiscard
```

例如 Brush UV：

```text
u < 0
u > 1
```

然后 shader：

```glsl
if (uv.x < 0.0 || uv.x > 1.0)
    discard;
```

这是合法行为。

最终检查：

```text
unexpectedOob == 0
```

# 25. Reference Tangent

对于每个 Fixture：

```text
Treference
```

由数学函数生成。

例如水平：

```text
T = (1,0)
```

圆：

```text
P(t) = (cx + r cos(t),
        cy + r sin(t))
```

理论切线：

```text
T(t) =
normalize(
    (-sin(t), cos(t))
)
```

---

# 26. 实际 Tangent

执行：

```text
StrokeFrameSolver
```

得到：

```text
Tactual
```

---

# 27. Angle Error

公式：

```text
dotValue =
clamp(
    dot(Tactual, Treference),
    -1,
    1
)

angleError =
acos(dotValue)
```

单位：

```text
degree
```

# 35. 第二步调 Tangent Window

例如：

```text

3
5
7
```

原则：

```text

→ 越稳定
→ 延迟越高
```

# 195. 最重要的工程思想

整个项目以后不再用：

```text
“这个效果够不够好？”
```

作为主要问题。

而改成：

```text
“哪个变量偏离了预期？”
```

例如：

```text
PNG 不像
→ UV / Alpha / Color / Filter

纹理转弯错误
→ StrokeFrame / Rake / Phase

干刷不自然
→ Load / Paper / Bristle

水彩扩散错误
→ Velocity / Diffusion

边缘太黑
→ Evaporation / Absorption / Deposition

回流太强
→ Rewet / Velocity impulse / Locality

性能差
→ Simulation cost / Resolution / Active region
```

# 196. 最终执行助手必须遵守的 12 条铁律

```text
1. 不用手动画作为核心正确性测试。
2. 所有核心测试必须有固定 Fixture。
3. 所有 Fixture 必须可重放。
4. 所有 Gate 必须产生 Evidence。
5. 所有数学指标必须有定义。
6. 所有视觉指标必须有固定测试图。
7. 参数一次只调整一个主要变量。
8. 不允许为了 PASS 私自放宽阈值。
9. FAIL 不允许跳 Gate。
10. BLOCKED 不等于 PASS。
11. 前置 Gate 回归必须始终通过。
12. 物理系统先验证不变量，再调视觉效果。
```
